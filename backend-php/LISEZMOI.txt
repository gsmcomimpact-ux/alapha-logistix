ALPHA LOGISTIX — INSTALLATION SUR IFASTNET (PHP + MySQL)
=========================================================

Contenu du dossier
  public_html/   -> à envoyer à la racine du site (dossier « htdocs » ou « public_html »)
  database.sql   -> à importer dans MySQL (phpMyAdmin)

Adresses du site une fois installé
  Site public ........ https://alphalogistixgroup.com
  Administrateur ..... https://alphalogistixgroup.com/administrateur
  Utilisateurs ....... https://alphalogistixgroup.com/utilisateur


ÉTAPE 1 — Créer la base de données
  1. Panneau iFastNet > « MySQL Databases » : créez une base, un utilisateur et un mot de passe.
  2. Notez : nom de la base, utilisateur, mot de passe ET l'adresse du serveur MySQL
     (souvent « localhost » ou du type sqlXXX.hébergeur.com — elle est indiquée dans le panneau).
  3. Ouvrez phpMyAdmin, sélectionnez la base, onglet « Importer », choisissez database.sql, validez.

  (Alternative sans phpMyAdmin : après l'étape 3, ouvrez /api/setup.php et utilisez « Étape A — Créer les tables ».)

ÉTAPE 2 — Envoyer les fichiers
  1. Avec le gestionnaire de fichiers ou un client FTP, envoyez TOUT le contenu de public_html/
     dans le dossier racine du site (là où se trouve index.html du domaine).
  2. Vérifiez que le fichier « .htaccess » (fichier caché) est bien présent à la racine ET dans le dossier api/.

ÉTAPE 3 — Configurer
  1. Dans le dossier api/, copiez config.sample.php en config.php, puis modifiez :
       db_host / db_name / db_user / db_pass  -> valeurs de l'étape 1
       setup_key                               -> une longue phrase secrète aléatoire (20+ caractères)
       mail_from                               -> une boîte e-mail du domaine (ex. noreply@alphalogistixgroup.com)
       commercial_email                        -> commercial@alphalogistixgroup.com (reçoit les cotations)
  2. Créez les boîtes e-mail correspondantes dans le panneau (au minimum noreply@ et commercial@).

ÉTAPE 4 — Créer le compte administrateur
  1. Ouvrez https://alphalogistixgroup.com/api/setup.php
  2. Saisissez la clé setup_key et choisissez le mot de passe de l'administrateur principal
     (compte : djimba.chamid@alphalogistixgroup.com).
  3. IMPORTANT : supprimez ensuite le fichier api/setup.php du serveur.

ÉTAPE 5 — Vérifier
  - https://alphalogistixgroup.com/api/health doit afficher {"ok":true}
  - https://alphalogistixgroup.com/administrateur : connexion avec l'e-mail et le mot de passe de l'étape 4.
  - Panneau « Personnel » : ajoutez chaque membre avec son adresse @alphalogistixgroup.com ET un mot de passe
    (bouton « Générer » possible). Le membre se connecte aussitôt sur /administrateur avec son e-mail et ce mot de
    passe, puis peut le changer. Pour réinitialiser un mot de passe : « Modifier » > « Nouveau mot de passe ».
    Communiquez le mot de passe à l'intéressé de façon sécurisée (jamais par un canal public).
  - Envoyez-vous une demande de cotation depuis le site : elle doit arriver sur commercial@.


ÉTAPE 6 (FACULTATIVE) — Connexion des clients avec leur compte Google / Gmail
  Sans cette étape, les clients peuvent déjà s'inscrire et se connecter avec n'importe quelle adresse
  (y compris @gmail.com) + un mot de passe. Pour ajouter le bouton « Continuer avec Google » :
  1. https://console.cloud.google.com > créez un projet > « APIs et services » > « Écran de consentement OAuth »
     (type Externe, nom « Alpha Logistix »), puis publiez l'application.
  2. « Identifiants » > « Créer des identifiants » > « ID client OAuth » > type « Application Web ».
  3. Dans « Origines JavaScript autorisées », ajoutez : https://alphalogistixgroup.com
  4. Copiez l'ID client (se termine par .apps.googleusercontent.com) dans api/config.php :
       'google_client_id' => 'VOTRE_ID_CLIENT.apps.googleusercontent.com',
  Remarques : le personnel (@alphalogistixgroup.com) et l'administrateur principal ne peuvent PAS se connecter
  avec Google : ils utilisent toujours e-mail + mot de passe.


CE QUI FONCTIONNE AVEC CETTE VERSION
  - Comptes e-mail + mot de passe (administrateur, personnel @alphalogistixgroup.com, clients avec n'importe quelle adresse, Gmail incluse)
  - Changement de mot de passe, « mot de passe oublié » par e-mail, confirmation d'adresse par e-mail
  - Suivi public par numéro de référence, suivi détaillé et documents dans l'espace utilisateur
  - Demandes de cotation (visiteurs sans compte inclus) enregistrées ET envoyées par e-mail au service commercial
  - Notifications de suivi aux clients par e-mail (option notify_clients_by_email dans config.php)
  - Mise à jour presque instantanée : les écrans se rafraîchissent toutes les ~6 secondes

DIFFÉRENCES PAR RAPPORT À LA VERSION FIREBASE
  - Connexion Google : réservée aux clients et facultative (étape 6). Le personnel n'utilise que e-mail + mot de passe.
  - Les règles d'accès sont appliquées par le serveur PHP (api/permissions.php), plus par firestore.rules.

SAUVEGARDES
  Exportez régulièrement la base depuis phpMyAdmin (onglet « Exporter »). Les documents envoyés par les
  utilisateurs sont stockés dans la base : elle contient donc toutes les données.

DÉPANNAGE
  - PREMIER RÉFLEXE : ouvrez https://alphalogistixgroup.com/api/health — la page dit exactement ce qui ne va pas
    (base injoignable, mot de passe refusé, tables manquantes, administrateur non créé...).
    Tout est correct quand elle affiche "ok":true et "admin_created":true.
  - Message « Erreur serveur : ... » à la connexion : il reprend le diagnostic ci-dessus.
  - Page blanche ou erreur 500 sur /api : vérifiez config.php (identifiants de la base) et la version de PHP
    (choisir PHP 8.0 ou plus récent dans le panneau).
  - /administrateur affiche une erreur 404 : le fichier .htaccess de la racine est absent ou mod_rewrite désactivé.
  - Aucun e-mail reçu : vérifiez que la boîte mail_from existe ; contrôlez les courriers indésirables ;
    certains forfaits gratuits limitent la fonction mail() de PHP.
  - Connexion impossible après plusieurs essais : le blocage anti-abus dure 15 minutes.
